# v1.0.0-rc.27 Upgrade Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Integrate signed upstream `v1.0.0-rc.27` into the self-use release, preserve every rc.26 customization, rebuild the four themed backups, and create the matching development branch without switching production.

**Architecture:** The release branch is created from the prior integrated release and receives the upstream tag through one signed non-fast-forward merge. Conflict resolution adopts rc.27's centralized channel constraints and task-plugin architecture while retaining the fork's model matching, billing, compatibility, and usage-log contracts. The four backups are reconstructed as theme-only diffs from the clean upstream tag.

**Tech Stack:** Go 1.22+, Gin, GORM v2, React 19, TypeScript, Bun, Git with SSH signing, SQLite/MySQL/PostgreSQL compatibility

**Spec:** `docs/superpowers/specs/2026-08-30-rc27-upgrade-design.md`

## Global Constraints

- Work only in `.local-tests/worktrees/rc27`; the primary rc.26 checkout remains untouched.
- Check `.git/worktrees/rc27/index.lock` before every Git command and remove it only when present.
- Preserve the independently buildable `relaykit/` module and use `GOWORK=off` for its gate.
- Keep the four approved customization themes separate and signed.
- Never push to `upstream` and never create a custom version tag.
- Do not push the currently monitored production release or switch Zeabur without the exact phrase `確認發布`.
- Treat rc.27's `TaskPlugin` migration as additive, but require three-database evidence before production.
- Reconfigure and compare every production video-model price before production cutover.
- Every commit must be signed and contain exactly `Co-authored-by: Codex <noreply@openai.com>`.
